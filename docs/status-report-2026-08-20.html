LiveOngoing

Error monitoring with Sentry

Sentry has been monitoring backend errors in production for some time now, catching and surfacing issues automatically instead of relying on someone noticing. This period, local development was separated from production reporting, so test errors no longer pollute the live error feed.

Impact: cleaner signal means real production issues get noticed and fixed faster.
LiveAug 5–20

Shopify orders, right inside the chat

Customers can ask the bot to check an order's status, request a refund, cancel an order, or update a shipping address — with a confirmation step before anything changes. Live in production and verified against a real store, including a refund processed end to end.

Impact: deflects order-status and post-purchase requests from support queues into self-serve chat.
LiveAug 13–18

Amazon order tracking (Pending Testing)

Amazon-connected stores can now offer order-status lookups the same way Shopify does. This is read-only for now — refunds and cancellations are on hold until Amazon approves the additional API access they require.

Impact: extends the same self-serve order support to Amazon-based merchants, no additional setup required.
LiveAug 18–20

AI-drafted Knowledge Base articles, with human review

A new pipeline watches for recurring support gaps and drafts Knowledge Base articles to fill them automatically. Nothing publishes unread — admins get a Pending Review queue to approve, edit, or reject each draft first.

Impact: shrinks the time from "customers keep asking this" to "there's an article for it," without sacrificing editorial control.
ShippedAug 18

Cleaner admin experience

The Diagnostics and Integrations pages in the admin portal were rebuilt for clarity, and the organization/tenant switcher was unified into a single control — no more two dropdowns that could quietly disagree with each other.

ShippedAug 18

Platform hardening

Removed exposed credentials from the codebase, added automated scanning to catch that class of issue before it happens again, and put automated test coverage in place for both the web and mobile apps for the first time.

Impact: closes the highest-severity items from a full security and reliability review — no open findings remain.
ShippedAug 18–20

Steadier under outages

The platform now degrades gracefully instead of stalling when the identity provider or a connected service is slow or unreachable — including a fix for a page load that could previously hang for tens of seconds.

ShippedAug 18

Mobile app update & legacy retirement

Shipped mobile app version 1.0.42 and fixed the App Store submission credentials for smoother future releases. Separately, the old legacy ticketing system that Project IQ was migrating away from has now been fully retired — every workflow runs natively.

Current state

  • Shopify integration — connected and configured in production at piq.99technologies.com; order lookup, refunds, cancellations, and shipping updates have been built and verified against a test store. Basic configuration and integration are done — the complete, production-grade use case still needs to be properly implemented and hardened before general rollout.
  • Amazon integration — connected and configured for read-only order tracking. Basic configuration and integration are done, but the complete use case still needs to be properly implemented; refunds/cancellations also remain blocked pending Amazon's approval of additional API access.
  • Knowledge Base curation — pipeline and review workflow are shipped and ready. Awaiting its first live review cycle with real support content.
  • Web & mobile chat apps — audited this week and confirmed at full feature parity. Every user-facing capability on web also exists on mobile, and vice versa.
  • Sentry error monitoring — live on both the main application and the ITSM service. Local development no longer reports into the same feed as production, so the signal stays clean.
  • Platform reliability — automated tests passing at 235/235, secret-scanning active, CI coverage extended to both frontends. No known open security issues.

Plan to final release

2–3 weeks

Testing, verification, and bug fixing of the full application as it stands today — not new feature or module development — run at roughly half a day, about 4 focused hours, dedicated to it per working day.

Week 1Days 1–5

Full-application testing pass

Systematic testing across the entire application as it exists today — chat/bot core, Shopify, Amazon order tracking, Knowledge Base curation, and the admin portal, on both web and mobile. Every issue found gets logged and triaged immediately rather than deferred.

Week 2Days 6–10

Bug fixing & re-testing

Fix everything flagged in Week 1, then re-test each fix against the whole application — not in isolation — to catch any regression the fix itself might introduce. Any areas that couldn't be fully verified in Week 1 (Amazon, KB curation) get finished here as account access allows.

Week 3Days 11–15

Final regression & sign-off

One more complete pass across the full application after all fixes land, then release sign-off. Best case, everything closes clean by the end of Week 2 and this week is a formality; if not, this is the outer bound of the estimate — not an open-ended tail.

Estimate assumes roughly 4 focused hours a day, not full-time availability — a full working day on this would compress the timeline; fewer hours per day would push it toward the 3-week end.
