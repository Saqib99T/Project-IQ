01

Tenant User

"I have a problem." The chat widget, from the outside in.

chat widget
Act 1 · Tenant User live login

Bot-first. Human when it matters.

  • Signed in, not typed in — single sign-on, product-scoped session
  • KB-first answers — quick-reply buttons before any ticket is opened
  • Ticket creation in the chat — quick-issue chips, attachment, one confirm
  • Ask for a human, anytime — queued with a live wait estimate, then a real conversation
Surface: chat widget (/bot)
02

Tenant Operator

"I handle it." The same person, two roles: live chat and the ticket behind it.

operator console + ITSM
Act 2 · Tenant Operator live login

One console. One ticket. One identity.

  • Queue — claim the waiting conversation, see why it escalated
  • Live session — canned responses, AI-draft co-pilot, resolve
  • Same login, ITSM tier — the Operator role maps straight onto the ticket system
  • Internal notes — visible only from agent tier up — end-users never see them
One identity, two role vocabularies — not two separate systems
Surfaces: Operator Console (/portal) · ITSM tickets (agent tier)
03

Tenant Admin

"I run the operation." SLA, on-call, and governed root-cause analysis.

the centerpiece
Act 3 · Tenant Admin live login

Everything a tenant owns, self-serve.

  • Portal — analytics, interaction history, live monitor, users
  • Integrations, self-serve — Teams/webhook connectors, scoped to just this org
  • ITSM admin — SLA/OLA/UC, on-call & escalation, automation, audit log
  • Reliability — error-budget gauges on live services
Surfaces: Portal admin (/portal) · ITSM admin (/itsm)

04

Super Admin

"I run the platform." Every tenant, isolated and controlled from one seat.

cross-tenant
Act 4 · Super Admin live login

One extra sidebar group. A very different reach.

  • Organizations — every tenant, side by side, read-only stats
  • Tenant switcher — flip context in one click, everything reloads scoped
  • Routing rules — platform-level, shapes every tenant's queue behavior
  • No "create tenant" button — provisioning is a signed webhook, by design
Surface: Portal — Platform group
Act 4 · continued

Isolation you can click, not just claim.

Blue Team

  • Its own users, tickets, SLA agreements
  • Its own RCA pipeline, its own KB
  • Can't see Green Team's data — ever

Green Team

  • Same product, completely separate tenant
  • Independent identity, independent history
  • Row-level security, not a UI filter
Bonus

Support, from your pocket.

The mobile app mirrors the chat widget exactly — same SSO, same handoff flow — and adds one manager-only touch: approve, reject, or waive an RCA straight from a phone.
