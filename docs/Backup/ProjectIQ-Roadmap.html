Part 1 · Pay Down
Improve What Exists
Quality, reliability and security gaps observed across the chatbot, portal, action server and ITSM service during recent work.
🚀 Engineering & delivery
1Repo hygiene — binaries in git
P1M
.git is 2.1 GB: a 70 MB APK + ~a dozen 39 MB Rasa model tarballs are tracked, bloating every CI checkout. Move models to a model store, APK to EAS/Releases; rm --cached + ignore.
2Prod deploy pipeline + staging
P1M–L
Deploys are manual scp+ssh across two repos, prod isn't git, and the deploy doc was stale (wrong IP). Add CI/CD, a staging env, smoke tests and one-command rollback.
3Finish logging migration
P2S–M
~220 print()s remain outside hot paths. Convert them, lint to block new ones, and extend error-alerting to Rasa-core + the ITSM containers (today: admin API + action server only).
4Test coverage gaps
P2M
295 tests are all backend/data — zero frontend/e2e tests (widget, portal, itsm-app, mobile) and none for the new tracing/alerting code. Add Playwright for the chat→ticket→handoff flow.
🔐 Security & reliability
5ITSM ticket-write RBAC
P1S–M
PATCH /tickets has no role check — any authenticated user can change status/priority (deferred earlier). Scope it: agents+ for priority/assignee; requester limited to resolving their own ticket.
6Secrets management
P2M
Post-Infisical there's no central secret store — creds in .env files + dev defaults in compose. Adopt a vault/manager, or document provisioning + rotation.
7Server-side guardrails & rate limits
P2S–M
Widget guardrails (PII/profanity/length) are client-side and bypassable. Enforce server-side; confirm the chat webhook + auth endpoints are rate-limited.
8Dependency & vuln cadence
P2ongoing
Rasa 3.6.20 pins an old stack (pydantic 1.10, redis<5, py3.10); the ITSM Trivy job flags image CVEs. Set a patching/base-image cadence.
🧱 Architecture & product
9Consolidate metrics
P2S
Observability had several broken/duplicated queries (missing tables, start_time, duplicated avg-response, ILIKE error-rate). Centralize metric SQL into one tested module; drop remaining heuristics.
10Web/mobile parity audit
P2S–M
Known drift: ticket-form chips vs dropdown; mobile renders ticket detail as markdown only (no structured comments card). Systematic pass against the parity rule.
11KB robustness & i18n
P3M
sentence_transformers missing locally breaks vector rebuild; KB had a NoneType crash (fixed). Harden ingestion, surface the existing kb_gaps data, consider localization (English-only today).
Part 2 · Build Next
New Capabilities
Where the platform can grow — several build directly on infrastructure that already exists (correlation IDs, the ITSM AI services, the automation engine).
🤖 AI & conversational
1LLM-augmented understanding
P1M
A Claude tool-calling fallback for low-confidence / out-of-scope NLU (hybrid with Rasa) — fewer "didn't understand" replies, less training burden, and the incremental path toward a Rasa→LLM migration.
2Conversation trace viewer
P2S–M
You now have end-to-end correlation IDs — build an admin view that reconstructs a whole turn across services by request_id. A cheap win on top of work already shipped.
3Operator AI co-pilot
P2M
Grow "suggest reply" into draft / rewrite / summarize / next-best-action, plus canned responses & macros for agents.
🎫 Support operations
4KB auto-drafting loop
P2M
ITSM already has a kb_drafter — auto-propose KB articles from resolved tickets and close the deflection loop.
5Deflection & CSAT analytics
P2S–M
Bot-resolved vs escalated rate, KB deflection, agent-performance dashboards — the data already lives in Postgres.
6Smart assignment + SLA escalation
P3M
Round-robin / load-based auto-assignment and breach-escalation chains, built on the existing automation engine.
7Approval workflows
P3M
The status enum already has pending_approval / approved / rejected — add the workflow for access & change requests.
📡 Channels & platform
8Email-to-ticket + email notifications
P2M
Inbound email creates/updates tickets — typically the most-requested omnichannel addition.
9Slack / Teams / WhatsApp + proactive outbound
P3L
Additional channels, plus scheduled / satisfaction-survey / status-push outbound messages.
10Error-alert inbox + integration marketplace
P3M
Surface the new error alerts as a managed admin inbox (not just notifications); expand inbound integrations/webhooks.
Sequencing
Where to Start

🎯 Highest bang-for-buck first

  1. Deploy pipeline + staging — de-risks every change after it; today's manual scp deploy is the biggest operational hazard.
  2. ITSM ticket-write RBAC — a real, open security gap (anyone can change any ticket's status/priority).
  3. Repo binaries cleanup — cheap, removes recurring CI checkout pain.
  4. LLM-augmented understanding — the strategic product lever; start as a low-confidence fallback, measure, then expand.
