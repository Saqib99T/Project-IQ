System Design
Architecture Overview
Layered, modular, production-ready. Each layer is independently scalable.
── PROJECT IQ PRODUCTION ARCHITECTURE ──────────────────────────────────
CLIENT LAYER Browser Widget Admin Panel /admin Operator Console /opt Mobile App (Expo) Rasa Action Server
↕ HTTPS / WSS / Socket.IO
EDGE LAYER Nginx → static assets served directly · Rasa upstream LB · rate limiting
APP LAYER Gunicorn + eventlet → Flask Blueprints ×12 → impl/ modules
Socket.IO ↔ Redis (pub/sub bus) ← shared across all workers
CACHE LAYER Redis → handoff config (60s) · themes (300s) · GLPI groups (300s)
In-process TTL Cache ← fallback when Redis unavailable
DATA LAYER pgBouncer :6432 → pool/20 → PostgreSQL primary + Read replica
pgvector ← KB semantic search with ivfflat index
AI LAYER Rasa NLU + Action Server → intent · entities · stories · rules · custom actions
EXTERNAL GLPI ITSM → auth · tickets · KB articles · group membership
Firecrawl ← self-hosted :3002 · web crawl + URL ingestion for KB

Extensibility & Growth
Scaling Made Simple
The system was architected so the most common scaling operations require zero code changes. Config files and guard code are already in place.
🟢 Zero Code Required — Config Only
🚀 Add Rasa Instance
infra/nginx.conf — add one line to upstream block: server 127.0.0.1:5006; Then: systemctl start rasa-core@2
5 minutes
🐘 Enable Read Replica
Set db_replica_host= in app.config.prod. Code already routes queue reads, operator stats, and analytics to replica — zero code changes.
5 minutes
⚡ More Workers
Change workers = 4 in infra/gunicorn.conf.py. Worker-0 guard already prevents duplicate background threads.
1 minute
🔴 Enable Redis Cache
Flip redis_enabled = true in config. Handoff config, themes, GLPI groups all use Redis with in-process TTL fallback.
1 flag
📊 Bigger DB Pool
Edit pool_size = 50 and max_client_conn = 500 in pgbouncer.ini. Restart pgBouncer.
15 minutes
🟡 Minor Work — Hours
🔁 Redis HA (Sentinel)
Add 2 Sentinel nodes, update Socket.IO message_queue URL to sentinel://. Update redis_cache.py client (~20 lines). Eliminates single Redis point of failure.
4 hours
🐘 PostgreSQL HA
Add Patroni or repmgr for auto-failover. Streaming replication setup script already written in infra/setup_pg_replica.sh. Update pgBouncer to point to Patroni VIP.
4–8 hours
🌐 Multi-server Flask
Shared Redis already in place. Add shared file storage (NFS/S3) for uploads. JWT auth is stateless — no sticky sessions needed. Add load balancer in front of Gunicorn instances.
1 day

Key Principles Applied
  • ◆
    Single Responsibility — each module owns one domain (operators, analytics, KB, etc.)
  • ◆
    Deferred Imports — blueprint layer imports impl/ at call time, zero circular imports
  • ◆
    Backward Compatibility — all existing imports still work via re-export facades
  • ◆
    Config-driven behaviour — Redis on/off, replica on/off, all via config flags
  • ◆
    No silent failures — Redis/replica unavailable → graceful fallback, not crash
